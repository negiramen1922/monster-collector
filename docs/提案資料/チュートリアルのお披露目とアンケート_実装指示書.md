新しいチュートリアル（ボタンを光らせて押させる、0-1〜0-5 の5本。`TUT_FLOW`）は main に入っているが、まだお知らせしていない。α0.5 でお披露目し、**遊び直してくれた人にお礼**、**ゲーム内のアンケートに答えてくれた人にさらにお礼**を渡す。

公開: α0.5 と同じ **10/8（木）12:00**（2026-10-06 決定）

## 1. チュートリアルの遊び直し

### 1-1. 今の問題

- 設定の「チュートリアルを再開」（`resumeTutorial`）は、**まだクリアしていない最初のステージ**から始める。進み具合を `clearedStages` から決めているので、5本ともクリアしている人は遊び直せない
- 2回目からはスタミナ10かかる（`TUTORIAL_REPLAY_STAMINA`）

### 1-2. 足すもの

- 設定とお知らせに「**チュートリアルを最初から遊ぶ**」ボタンを足す
- 押すと「遊び直しモード」になる（`STATE.tutReplay = { at: 0 }` のように、`clearedStages` とは別に進み具合を持つ）。0-1 から 0-5 まで、今のチュートリアルと同じ案内で進む
- 遊び直しモードの間は、**スタミナ0**、**初回クリアの石は出ない**（もうもらっているため）
- 途中でやめても、次に押したときは続きから（`tutReplay.at`）。スキップしたら遊び直しモードを抜ける（お礼は出ない）
- **0-5 をクリアしたら、1回だけお礼**: 星結晶 **360**。プレゼントボックスに届ける（`addPresentBoxGift('チュートリアルを遊んでくれたお礼', [{ type:'crystal', n:360 }])`）。`STATE.tutReplayRewarded = true` で2回目は出さない
- 対象は**お披露目（10/8 12:00）より前からいるプレイヤー**。新しく始めた人は、ふつうにチュートリアルの石（3,700）をもらうので、遊び直しのお礼は出さない（`tutReplayRewarded` を始めから true にする）
- 遊び直しを終えたら、アンケート（2章）へのボタンを出す

## 2. アンケート

### 2-1. 形

- ゲーム内のフォーム（オーバーレイ1枚。設定・お知らせ・遊び直しの終わりから開ける）
- **答えられるのは、チュートリアルを最後まで遊んだ人**（遊び直しを終えた人、または新しく始めて 0-5 をクリアした人）。チュートリアルについて聞くため
- 1アカウント1回。送ったら「送信ずみ」と出して、もう一度は送れない
- 期間: 10/8 12:00 〜 **10/22（木）23:59**（案）。期間を過ぎたらボタンを出さない

### 2-2. 質問（案）

| # | 質問 | 形 | 必須 |
| --- | --- | --- | --- |
| 1 | チュートリアルは分かりやすかったですか | 5段階（とても分かりにくい〜とても分かりやすい） | 必須 |
| 2 | チュートリアルの長さはどうでしたか | 短い / ちょうどよい / 長い | 必須 |
| 3 | 分かりにくかったところ（いくつでも） | 戦闘の流れ / ウェーブ / 奥義 / 陣形 / 属性と種族 / ガチャと星刻 / 遺物とルーン / とくになし | 必須 |
| 4 | 3で選んだところは、どう分かりにくかったですか | 自由記述 | 3で「とくになし」以外を選んだら必須（20文字以上） |
| 5 | 新しいバトルシステムはどうですか | 5段階（とても遊びにくい〜とても遊びやすい） | 必須 |
| 6 | いちばん直してほしいこと・足してほしいこと | 自由記述（**20文字以上**） | 必須 |
| 7 | そのほか、ご自由にどうぞ | 自由記述 | 任意 |

- 自由記述は最大500文字
- しっかり答えてもらうため、必須の自由記述は20文字以上（足りないと送れない）

### 2-2b. 画面（2026-10-06 決定）

見本: `docs/提案資料/アンケート画面の見本.html`（公開した見本 https://claude.ai/artifact/7tY22S6CVgQ9ocG9rRnurv と同じもの）。**この見本の見た目と動きのとおりに作る。**

- **飾りのない簡素な形**: シート1枚に、タイトル（金色）・ひとこと説明（お礼・1回だけ・期限）・質問を上から並べる・一番下に「送る」ボタンと「あと○問答えると送れます」の一行
- **質問は1問ずつ、シートより一段明るい面にのせる**（字が背景に埋もれないように）
- **白黒の差を強くしすぎない**: 背景は真っ黒にせず、字の白も少し落とす。見本の色:

| 役 | 色 |
| --- | --- |
| 外側の背景 | `#1a1630` |
| シート | `#241e3c` |
| 質問1つぶんの面 | `#2d2649` |
| 入力欄 | `#363056` |
| 字 | `#ebe4d6` |
| 補足の字 | `#c6bcdc` |
| タイトル・選択の色 | `#e3b35f` |
| 必須・エラー | `#f29aa7` |

  今のゲームの色（`--bg` `#0f0c1a`・`--text` `#f3ecdf` など）より、背景を明るく、字を暗くしてある。アンケート画面だけこの色にしてよい
- 字の大きさ: 質問 14px（太字）、選択肢 14px、補足 12px、入力欄 14px。行間はゆったり（1.6〜1.8）
- 選択肢はふつうのラジオボタン・チェックボックス（18px、選択の色は金色）。5段階は1〜5を横に並べ、両端の意味を下に書く
- 自由記述の下に文字数（○ / 20）。20文字に足りないうちは赤
- 答えていない必須の質問があるあいだは「送る」を押せない
- Q3で「とくになし」を選ぶと、ほかの選択肢は選べなくなり、Q4は答えなくてよくなる（入力欄を薄くする）
- 送ったあとの画面: 「送信しました」・お礼の文・「プレゼントボックスを開く」・「閉じる」
- まだ答えられないときの画面: 「チュートリアルを最後（0-5）まで遊ぶと答えられます」・「チュートリアルを最初から遊ぶ」ボタン

### 2-3. お礼

- 送ったら、**モンスター召喚券10枚**をプレゼントボックスに届ける（`addPresentBoxGift('アンケートのお礼', [{ type:'item', key:'gacha_char', n:10 }])`）
- `STATE.surveyDone['tutorial_2026_10'] = true` で2回目は出さない

### 2-4. 保存先と見かた

- 回答は Firestore の **`surveys/tutorial_2026_10/answers/{uid}`** に保存する（ドキュメントIDをuidにして、1人1件にする）
- 保存する中身: 質問1〜7の答え、送った日時、プレイヤーID・テイマーLv・クリアしたステージ数・持っている★5の数（答えを読むときに、どのくらい遊んでいる人かが分かるように）。名前・メールアドレスは入れない
- `firestore.rules` に足す:

```
match /surveys/{surveyId}/answers/{uid} {
  allow create: if request.auth != null && request.auth.uid == uid;   // 本人の場所に1回だけ作れる
  allow read, update, delete: if false;                               // プレイヤーからは読めない
}
```

- **答えの見かた**:
  - すぐ見るなら **Firebaseコンソール → Firestore Database → `surveys/tutorial_2026_10/answers`**
  - まとめて読むなら、**集計スクリプト `tools/survey_export.js`** を作る。Firebaseの管理用の鍵（サービスアカウント。リポジトリには入れない）で読み、**CSVと集計（5段階の平均、選択肢ごとの数）**を出す
- ルールの反映は `firebase deploy --only firestore:rules` か、コンソールに貼り付ける（ユーザーが行う）

## 3. テスト

- 遊び直し: 5本ともクリアずみのセーブで「最初から遊ぶ」→ 0-1 から始まる / スタミナ0 / 初回クリアの石が出ない / 0-5 のあとに360石が1回だけ / 2回目は出ない / 新しいセーブには出ない
- アンケート: 必須を埋めないと送れない / 20文字未満は送れない / 送ったら召喚券10枚が1回だけ / 2回目は送れない / チュートリアルを終えていないと開けない / 期間外はボタンが出ない
- 保存: 送信が失敗したら（オフラインなど）お礼を出さず、もう一度送れる
- 試験場（`?lab=tutorial`）では、Firestore に書かない
