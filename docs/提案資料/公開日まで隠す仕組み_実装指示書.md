# 公開日まで隠す仕組み 実装指示書

Oct 6, 2026 · @ねぎらーめん

`docs/提案資料/実装の段取り.md` の第2段の最初（D）。新キャラ（桃太郎・豊穣の女神の14体）と新しい遺物を先に index.html に入れておき、**イベントの開始日時まで、プレイヤーに見える場所に出さない**ための仕組み。

今は、モンスターを足すとすぐにガチャ・図鑑・選択チケットなどに出てしまう。イベント（`EVENTS`）は `startAt` で隠れるが、モンスターと遺物には日付がない。

---

## 1. 形

### 1-1. データ

- モンスター（`monster-data` の JSON）に **`releaseAt`**（ISOの日時。例 `"2026-10-13T15:00:00+09:00"`）を足せるようにする。書いていないモンスターは、今までどおり最初から公開
- 遺物（`RELICS`）にも同じ `releaseAt` を足せるようにする
- 新キャラ・新遺物の `releaseAt` は、そのイベントの `startAt` と同じにする

### 1-2. 判定

```js
// 試験場(?lab=...)では日付に関係なく全部見える
const ANY_LAB = typeof location !== 'undefined' && /[?&]lab=/.test(location.search || '');
function isReleased(x){ return ANY_LAB || !x || !x.releaseAt || Date.now() >= new Date(x.releaseAt).getTime(); }
function releasedMonsters(){ return MONSTERS.filter(isReleased); }
```

- 毎回 `Date.now()` を見るので、遊んでいる途中で公開時刻を過ぎても、画面を開き直せば出る（イベントの `activeEvents()`・`addonOpen()` と同じ考え方）
- 時計は端末の時計。イベントと同じなので、ここでは変えない

### 1-3. 変えないもの

- `MON_BY_ID`・`MON_ORDER`・`MON_BY_NAME` は全部のモンスターのまま（IDから引く表なので、隠す必要がない）
- `AVG_BASE_HP`（被弾SPの基準HP）は全部のモンスターで計算したままにする。公開時刻をまたぐと値が変わってしまい、キャッシュとずれるため。新キャラ14体ぶんで少し変わるが、公開後と同じ値になるだけ
- イベントのステージに敵として出すのは、日付の前でもよい（イベント自体が `startAt` まで隠れている）

## 2. 直す場所

`MONSTERS` を直接使っている27か所のうち、**プレイヤーに見える一覧**を `releasedMonsters()` に変える。関数名は今のコード（`python3 tools/extract.py` で出した `tools/game.js`）のもの。

| 関数 | 何の一覧か | 直す |
| --- | --- | --- |
| `pickMonsterOfRarity` | ガチャの排出（常設・★4の脇役・★5の脇役・そのレアリティ全体） | **直す**（4か所） |
| `doBeginnerGacha` | ビギナーガチャの★5確定枠 | **直す** |
| `renderSelectPickupPanel` / `renderSelectPickerSheet` | セレクトピックアップで選べるキャラ | **直す** |
| `renderBag` | ★○選択チケットで選べるキャラ（属性のボタンも） | **直す** |
| `renderDex` / `filterPool` | 図鑑と、その数（「○ / 全体 体」） | **直す** |
| `renderFilterControls` | 図鑑の「★上げできる」の数 | **直す** |
| `abyssStage` | 深淵回廊の敵 | **直す**（日付の前に敵として出さない） |
| プロフィールの「○ / 全体」（2か所） | 図鑑の達成数の分母 | **直す** |
| タイトル画面の `titleMonsterPick` | タイトルに出るモンスター | **直す** |
| `homeBanners` の `dungeonMon` | ホームのバナーの絵 | **直す** |
| フレンドのプロフィールの `clampInt(p.monsters, 0, MONSTERS.length, 0)` | 読み込みの上限 | 直さない（上限なので全体でよい） |
| `AVG_BASE_HP` | 被弾SPの基準 | 直さない（1-3） |
| `MON_BY_ID` などの表 | IDから引く表 | 直さない |
| 試験場（バベル・`?lab=`） | 試験場の一覧 | 直さない（試験場では全部見せる） |

遺物:

| 関数 | 何の一覧か | 直す |
| --- | --- | --- |
| `relicsOfStar` | 遺物ガチャの排出 | **直す**（`isReleased` を足す） |
| `relicFilterPool` | 遺物図鑑 | **直す** |
| `exclusiveRelicForMon` | 専用遺物を引く | 直さない（主役がまだ出ないので、呼ばれない） |

上の表にない場所で `MONSTERS` や `Object.values(RELICS)` を使っているところがあれば、同じ基準（プレイヤーに見える一覧なら直す）で判断し、この表に書き足すこと。

## 3. 試験場

- `?lab=momotaro` と `?lab=freyja` を足す（`モモタロウイベ_実装指示書.md` の1章。豊穣の女神も同じ形）。本番のセーブとクラウドに書かない（`LAB_MODE` / `TUT_LAB` と同じガード）
- `?lab=` で開いたときは、日付の前でも新キャラ・新遺物が全部見える（1-2の `ANY_LAB`）

## 4. テスト（`tools/release_gate_test.js` を新しく作る）

`Date.now` を差し替えて、公開時刻の前とあとで確かめる。

- 公開前: `pickMonsterOfRarity(5)` を1000回引いても新キャラが出ない。ビギナーガチャ・選択チケット・セレクトピックアップ・図鑑・深淵の敵にも出ない。遺物ガチャと遺物図鑑に新遺物が出ない
- 公開後: 同じ場所に出る
- 図鑑の分母が、公開前は今の数、公開後は14体ぶん増える
- `releaseAt` を書いていないモンスターは、いつでも出る
- 既存のテスト（ガチャ・図鑑・深淵・ビギナーガチャ）がすべて通る

## 5. 終わったら

- `実装の段取り.md` の D を「実装ずみ」にする
- 桃太郎・豊穣の女神の新キャラは、この仕組みに `releaseAt` を書いて入れる（第2段の E・F）
