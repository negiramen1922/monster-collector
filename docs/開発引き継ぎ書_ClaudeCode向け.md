## 0. このプロジェクトの前提

- **形態:** ほぼHTML1ファイルで完結します(画像・効果音・データはすべてファイル内に埋め込み)。外部を使うのは2つだけです。**BGM**は `assets/bgm/` の外部ファイル(埋め込むと9.7MB増えるため)、**Firebase SDK**はログイン時にCDNから動的importします。
- **動かし方:** ブラウザでファイルを開くだけです。ビルド手順はありません。
  - `file://` で直接開くと `fetch` がブロックされるため、BGMは `<audio>` 要素での再生にフォールバックします(音は鳴りますが、曲の切り替え時のフェードがありません)。
  - フェードまで含めて本番と同じにするには、HTTPで配信してください(`python3 -m http.server` など)。`tools/_serve.py` が画面テスト用にこれを行います。
- **表示:** スマートフォンの縦画面が基準です(375×667でレイアウトが崩れないこと)。UIの文言はすべて日本語です。
- **保存:** ログインしたアカウントごとに、ブラウザの `localStorage` とFirestoreの両方へ保存します(端末をまたいで続きから遊べます)。読めない・古い形式のときは初期化されます。詳しくは `docs/認証とクラウドセーブ.md`。
- **ログイン:** 起動するとタイトル画面が出て、Google・メールアドレス・ゲストから選びます。ログイン済みなら自動で通過します。**`file://` で直接開くとログインはできません**(ゲーム自体は動きます)。
- **現在の規模:** `index.html` 約3.3MB(画像2.5MB、効果音0.2MB、アイコン0.2MB、データ0.03MB、コードはJS約6,200行・CSS約1,450行)＋ `assets/bgm/` 約7.0MB。

## 2. 戦闘エンジン(engine v3)

### 進行

- **ラウンド制:** 毎ラウンド、生存キャラがSPD順に1回ずつ行動します。最大30ラウンドで時間切れ(敗北)。
- **1行動の流れ:** `runNextAction()` → `takeTurn(u)` → `startTurn`(状態異常のダメージ・CT減少) → 行動 → `endTurn`(継続回復・バフの残りターン)。
- **演出:** 行動キャラを強調してから、`HIT_DELAY_MS`(300ms÷倍速)後にダメージ・エフェクト・HPバーが動きます。
- **ログ:** 攻撃・状態異常に加えて、バフ/デバフ・回復・シールド・挑発・免疫・SP増減を `applyEffect` が1行ずつ出します。
  パッシブは、陣容で決まるもの(`onBattleStart` を持つもの)を戦闘開始時に、耐える・復活する系(`survive`/`onDeath`)を発動時に出します。
- **ユニットの詳細:** 戦闘中にユニットをタップすると、HP/SP・ステータス・かかっている効果・パッシブ・技が見られます
  (`showUnitInspect`)。必殺技を予約できる状態の味方だけは、タップが予約の切り替えのままです。

### ダメージ計算

```
raw = STR × (1+STRバフ) × 威力 × (1+与ダメージ補正) × 属性倍率 × 会心 × 乱数(0.95〜1.05)
dmg = max(raw × 10%, raw − 防御) × (1 − 被ダメージ軽減)
```

- **防御:** 行動ごとに物理(pdef)か魔法(mdef)を参照します。
- **被ダメージ軽減:** 足し算(上限80%)。「被ダメージアップ」は引き算されます。
- **属性:** 9属性。「火→草→水→火」「土→雷→風→土」「光⇔闇」で1.5倍/0.7倍。

### 技データ(kit)

`MONSTER_KITS[モンスターID] = { normal, skill1, skill2, passive, ult }`。技は「効果の組み合わせ」で書きます。

```js
m128: { // フレイムリザード
  normal: { name:'火の牙', desc:'威力100%', atk:'phys', tgt:'single', pow:1.0 },
  skill1: { name:'燃える牙', desc:'…', ct:2, atk:'phys', tgt:'single', pow:1.6,
            onHit:[{ st:'burn', chance:0.3 }] },
  passive:{ name:'俊敏な尾', desc:'…', dmgBonus: (u, t) => effSpd(u) > effSpd(t) ? pv(u, 0.1) : 0 },
  ult:    { name:'フレイムダイブ', desc:'…', sp:80, atk:'phys', tgt:'single', pow:3.0,
            bonusIf:[{ cond:'burned', add:0.3 }] },
},
```

**主なフィールド**

| 種別 | 値 |
|---|---|
| `tgt` | single / any(後衛も) / back / lowest / lowestAny / frontAll / backAll / all / random / row / column / self / allies / allyLowest / allyGuard / allyTop |
| `atk` | 'phys' / 'mag' |
| 攻撃 | `pow`(STR倍率)、`hits`、`hitMult`、`defIgnore`、`ignoreDef`、`critBonus`、`bonusIf`、`extraIf`、`lifesteal`、`shareHeal` |
| 命中時 | `onHit:[{ st, debuff, v, flat, turns, chance, drain, followUp }]` |
| 支援 | `effects:[{ to, buff, v, turns, heal, shield, taunt, cleanse, cleanseDebuff, ward, immune, spGain, drain, redirect, firstStrike }]` |
| 特殊 | `run: ctx => {…}`(独自処理。`dealHits` `applyEffect` `hpCost` `vanishThenStrike` などを使う) |

**パッシブのフック:** `onBattleStart` `onTurnStart` `onTurnEnd` `onHitBy` `onHitTarget` `onEvade` `onCrit` `onKill` `onDeath` `onAllyDeath` `onDamaged` `onSkillUsed` `survive` と、数値を返す `strBonus` `spdBonus` `defBonus` `cutBonus` `dmgBonus` `critBonus` `critDmgBonus` `evadeBonus` `healBonus` `healRecvBonus` `hateBonus` `thornsBonus` `immuneTo` `reflectOnBreak` `cleanseOnHeal` `stackIcon`。

**レベル補正:** スキル・必殺技は `sv(u, 値, kind)`、パッシブは `pv(u, 値)` を通します（1Lvごとに+5%）。

### 状態異常・バフ

| 名前 | 内容 |
|---|---|
| やけど | 付与側STRの40%、2ターン。自分のターン開始時にダメージ。受ける回復-30%。シールドから削る |
| 毒 | 最大HPの2%×層(最大5層)、5ターン。1層の上限は付与側の最大HPの20%。シールドを通らない |
| 気絶 | 次の行動を1回休む |
| シールド | 層ごとに時間を数える。合計は最大HPの50%まで |
| 免疫(ward) | 状態異常かデバフを1回だけ防ぐ。SP減少は防がない |
| そのほか | STR/SPD/物理防御/魔法防御の上下、被ダメージ軽減、被ダメージアップ、回復阻害、回避、継続回復、挑発、トゲ、肩代わり、石像化ほか |

**バフの持続:** かけたターンは数えません(`addBuff` の `skip`)。同じ種類は重ならず、大きい値・長い時間が残ります。

### ボスの仕掛け(現在は未使用)

`GIMMICKS` と `runGimmick()` に、激昂・召喚・シールド・全体攻撃などの仕組みが残っています。現在のクエストのボスは「★4のモンスターをそのまま出す」方針なので、どのステージにも設定していません。イベントボスなどで再利用できます。

## 4. クエスト(ステージ)

- **定義:** `QUEST_TIERS`(難易度)＋`QUEST_SPEC`(ステージごとの構成)。`buildQuestStages()` が `STAGES` を組み立てます。
- **構成の書き方:** `fixed: [{ f:['m21','m16'], b:['m29'] }, …]`。`f`=前衛、`b`=後衛、`*`付き(`'*m60'`)がボスです。
- **敵の強さ:** 難易度ごとの★(初級1・中級2・上級3。モンスター本来の★が上ならそちら)と、`QUEST_LV_ADJ` の調整値で決まります。

```js
const QUEST_LV_ADJ = {
  q1_01: { lv: 5 },        // 通常の敵のレベル(推奨Lvからの差)
  q1_05: { bossLv: 1 },    // ボスだけレベルを上げる
  // star / bossStar も指定可能(現在は未使用)
};
```

- **敵の強さの基準値:** `ENEMY_POWER = 1.1`。全ステージ共通で、ここを動かすと全体の難易度が大きく変わります(1.0で大半が勝率90%以上、1.25で大半が30%以下)。
- **現在の構成:** チュートリアル3＋初級・中級・上級 各10の33ステージ。超上級・極上級は `disabled: true` で未実装です。

## 5. データを追加・差し替える手順

### モンスターを追加する

1. `monster-data` に1件追加します。必須項目は `id, name, element, rarity, role, family, tribe, species, statType, hp, str, pdef, mdef, spd, hate, desc, sprite`。
2. `MONSTER_KITS` に技を追加します(なければロール標準技が使われます)。
3. 攻撃の見た目が武器と合わない場合は `MONSTER_MOTION` に追加します(slash/strike/claw)。

### 立ち絵を追加する

元画像(透過PNG)を、余白を詰めて256px角・WebP(画質90)にし、`sprite-data` に `"<IDの数字>": "data:image/webp;base64,…"` として入れます。背景を抜いたときのマゼンタが残っている場合は、周囲の色で埋めてから変換します(過去の作業では最大2,600画素)。

### 効果音・BGM

- **効果音:** モノラル・80kbps・無音を詰めたMP3。`sfx-data` に入れ、`SFX` で音量と再生速度を指定します。
- **BGM:** モノラル・96kbps。末尾のフェードを切り、末尾2秒を先頭2秒に重ねて、切れ目なくループするようにしています。ファイルは `assets/bgm/<場面>.mp3` に置き、`bgm-data`(パスの一覧)と `BGM_TRACKS`(場面と音量)に追加します。

### アイコン

`icon-data` に `<ID>: data URIのPNG(96px角)` で入れます。必要なIDは「アイコン制作リスト.md」を参照してください。
属性アイコン(`elem_<属性>`)は実装済みです。素材(マゼンタ背景・左上にAIバッジ・2048px)からの変換は
`CHROMIUM_PATH=... python3 tools/make_icons.py` で行い、`ICONS` にファイル名とキーの対応を書きます。
`elem_*` が無い属性は、従来のSVGバッジにフォールバックします。**卵の画像(`egg_<色>_<状態>`)を入れると、ガチャ演出が自動でSVGから画像に切り替わります。**


## 7. バランス調整の手順

1. 難易度ごとの想定パーティを決めます(現在の基準は、属性の有利不利が出にくい無属性中心の5体、★4・スキルLv5〜7)。
2. `base54.js` で調整なしの勝率を測ります。
3. 目標(通常85%・ボス60%)から外れたステージを、次の順で直します。
   - **敵のレベル:** 通常は推奨±5、ボスは+0〜+25
   - **敵の構成:** 弱い/強いモンスターへの入れ替え、前衛の追加
   - **★:** 安易に上げない方針です(難易度ごとの基準から動かさない)
4. `check33.js` で全体を確認します。★1・★2のモンスターは元のステータスが低いため、上級では★3のモンスターを混ぜないと難易度が上がりません。
5. **どのステージにも出ないモンスターがいないか**を必ず確認します(`dump33.js` か、出番の集計スクリプト)。

## 8. コードの決まりごと

- **イベント:** クリックは `handlePhoneClick`、押下は `handlePhonePointerDown` の1か所に集約し、`data-*` 属性で分岐します。新しいボタンは、この2つに追記してください。
- **描画:** 画面ごとに `renderXxx()` が文字列(HTML)を返し、`render()` が差し替えます。戦闘だけは `renderBattleScreenOnly()` で部分更新します。
- **モーダル:** `#modal-layer` に `innerHTML` を入れて `show` クラスを付けます。閉じるのは `closeModal()`。
- **セーブ:** `STATE_VERSION`(現在6)が変わると初期化されます。形式を変えるときは必ず上げてください。
- **UIの文言:** すべて日本語。数字は `toLocaleString()` で桁区切りします。
- **コメント:** コード内のコメントは英語で統一しています(短く、なぜそうしているかを書く)。
- **絵文字:** 現在アイコン代わりに使っています。ドット絵が届き次第、`icon-data` の画像に置き換える予定です。

## 10. 既知の注意点

- **ファイルサイズ:** `index.html` は約3.3MBで、大半が立ち絵(2.5MB)です。BGM(約7.0MB)は `assets/bgm/` に分けてあり、最初のユーザー操作があるまで読み込まれません。
- **敵の強さの基準値:** `ENEMY_POWER` はわずかな差で全体の難易度が動きます。触るときは必ず全ステージを測り直してください。
- **属性相性の影響:** 参照パーティの属性で、ステージの勝率が大きく変わります(例: 上級5「炎の巨人の玉座」は、無属性中心で10%、水3体で90%以上)。難易度を測るときは、評価用パーティを固定してください。
- **★1・★2の風のモンスター:** 打たれ強いモンスターがいないため、風のステージが易しくなりがちです。
- **初級:** 序盤は易しめ(勝率90%以上)の調整です。
- **チュートリアル2:** 必殺技のヒントで戦闘が一時停止します。node のテストでは止まったままになるので、クラッシュテストではチュートリアルを除外しています。
- **CPU:** 開発環境のCPUは1コアです。調整の自動探索は並列にしても速くなりません。
