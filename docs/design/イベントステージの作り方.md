# イベントステージの作り方（α0.3 以降の新規イベント向け）

最終更新：2026-09-30

**これは新しくイベントを作るときのルールです。** すでに公開したイベント
（紅蓮の九尾 / 黄金の巨神 / 嵐呼ぶ神狼 / 奈落の王）の数字は動かしません。
新しいイベントには `EVENTS` の定義に **`econV2: true`** を付けてください。この1つのフラグで

- EXの脇役からもソウルが出る
- EX3の主役のソウルが「50%で1〜3個」になる（付けなければ 100%で1個）
- イベントショップのソウル枠が新しい形になる（主役10個×30回、★4は1体ずつ）

がまとめて切り替わります。

---

## 0. なぜこのルールがあるか

ソウルが落ちるのは次の3つだけでした。

| | 条件 |
|---|---|
| ボスとして出た | 必ず1個 |
| レア個体として出た | 必ず1個 |
| ★2以下の雑魚として出た | 20%で1個 |

そのため **★3以上で、どのステージでもボスにもレア個体になっていないモンスターは
ソウルの入手ルートがゼロ**でした。数えると **71体**（★3は41体=全部 / ★4は23体 / ★5は7体）。

さらにガチャだけで完凸する石コストは、ピックアップ中でも ★4で81,000石・★5で100,800石。
**ステージで取れるかどうかでコストが40〜60倍変わる**ので、「出るかどうか」が
完凸できるかどうかをほぼ決めていました。

EXは**スタミナを使わない**ので、石を1つも使わない唯一のルートになります。
だからEXの敵の顔ぶれが、そのまま「誰が育てられるか」を決めます。

## 1. ソウルのドロップ率（`EX_MOB_SOUL_RATE`）

| 枠 | EX1 | EX2 | EX3 |
|---|---|---|---|
| **主役（ピックアップ★5）** | 20%で1個 | 50%で1個 | **50%で1〜3個**<br>(1個50% / 2個35% / 3個15%) |
| **抱き合わせ★4**（`featured` に入れた★4） | 40% | 70% | **100%** |
| その他の★4以上 | 20% | 35% | **50%** |
| ★3以下 | 15% | 25% | **35%** |

同じ種類が1ステージに複数体出ても、判定は**1クリアにつき1回**です。

### この率で完凸まで何クリアか（EX3を回す前提）

| | 必要ソウル | 1クリアの期待 | 完凸クリア数 |
|---|---|---|---|
| 主役★5 | 4,800 | 0.825 | **5,819** |
| 抱き合わせ★4 | 3,900 | 1.00 | 3,900 |
| その他の★4 | 3,900 | 0.50 | 7,800 |
| ★3 | 3,150 | 0.35 | 9,000 |

**狙い**：抱き合わせ★4が主役より先に終わり（イベントの副賞として妥当）、
それ以外は主役より後になる。「主役を集めていたら他も勝手に完凸する」を避ける形です。

実際にはイベントのメインクエスト・ガチャ・イベントショップからも入るので、
上の数字より短くなります。

## 2. ステージに出すモンスターの数

**EXの各段でユニーク10体まで**。いまの6ステージは11〜14体で、少し多いです。

理由：EXが「石を使わないソウルのルート」なので、出る顔ぶれ＝育てられる顔ぶれになります。
広げすぎると1体ずつの価値が薄れ、絞りすぎると救えない子が増えます。

**10体の内訳の目安**

| | 体数 | 役割 |
|---|---|---|
| 主役（★5） | 1体 | 最終ウェーブの先頭（ボス） |
| 抱き合わせ★4 | 2体 | 最終ウェーブ。副賞 |
| その他の★4以上 | 2〜3体 | 狙って回す対象 |
| ★3以下 | 4〜5体 | 序盤ウェーブの顔。属性の世界観を作る |

**属性を1つに寄せすぎないこと。** 地属性は★3以上の12体のうち8体がタンクで、
地だけで組むと「硬いが殺してこない」敵編成になり、敵を強くしても戦闘が長くなるだけでした。
足りないロールは**同じ科（`family`）**から他属性を借りるのが自然です
（例：タイタン＝ジャイアント科 → オーガ・サイクロプス・ユミル・スルト）。

## 3. 段ごとの強さ（`EVENT_EX`）

| | 推奨Lv | ボスの★ | 雑魚の★ | 敵ワザLv | 敵の能力倍率 |
|---|---|---|---|---|---|
| EX1 | 70〜85 | 6 | 4 | 8 | 1.0 |
| EX2 | 200 | 8 | 5 | 10 | 1.0 |
| EX3 | 300 | 10 | 6 | 12 | 1.0〜1.35 |

**EX1の推奨Lvは70〜85にしてください。** EXの解放が「イベントステージ3クリア」
（推奨Lv50）に前倒しされたので、Lv100だと入口で詰みます。実測で、ステージ3を
クリアした直後くらいの編成（Lv70 ★4 ワザLv3・遺物ルーンなし・総BP約11,000）だと

- 既存のアバドンEX1（Lv100）：**勝率0%**（全編成で全滅）
- フェンリルEX1（Lv100）：92%
- Lv85 に下げた案：88%

でした。同じルールでもステージの敵編成で結果が大きく変わるので、**作ったら必ず
この編成で測ってください**（`tools/` のハーネスで測れます）。

**敵の能力倍率（`power`）は EX3 の調整用**です。地属性のようにタンク寄りの編成だと
×1.9でも勝率100%のままなので、倍率で締めるより先に「火力のある敵を混ぜる」ことを
検討してください。

## 4. ステージ効果（`EVENT_EX_RULES`）

3〜5本。書ける形は `who`（`species` / `element` / `role` / `family` / `ref`）×
`side`（`ally` / `enemy` / `both`）× `stat`（hp / str / pdef / mdef / spd）/
`dmgDealt` / `dmgTaken` / `when`（`lowHp30` / `lowHp50` / `fullHp` / `burned`）。

**作るときの目安**

- **編成が変わるルールを1本は入れる。**「この属性を入れると楽」「この編成だと無理」が
  はっきりするのが良いEXです（実測でも、壁だけの編成が10%、対策編成が70%と差が出ました）
- **属性の優遇だけに頼らない。** 雷属性は★4・★5の手持ちが弱く、「雷の味方 与ダメージ+50%」を
  付けても雷編成が最下位のままでした。属性補正では戦力差を埋められません
- **`when:'lowHp50'` は戦闘を短くするのに効く。**「敵のHPが50%以下のとき 受けるダメージ+80%」で
  硬い敵を崩せるようになります
- **★3の条件は「ウェーブ数×4ラウンド以内かつ全員生存」**（`RANK_ROUNDS_PER_WAVE`）。
  3ウェーブなら12ラウンド。硬い編成にすると20ラウンド超えになって★3が取れないので、
  作ったらラウンド数も測ってください

## 5. イベントショップ（`eventShopItems`）

| 商品 | 1回 | 価格 | 上限 | 合計 |
|---|---|---|---|---|
| 主役のソウル | 10個 | 150メダル | 30回 | 300個 |
| 抱き合わせ★4のソウル（**1体ずつ別の商品**） | 20個 | 60メダル | 各10回 | 各200個 |

主役は「1回20個×15回」から「1回10個×30回」に。**合計300個は今までと同じ**で、1回を軽くして
買うタイミングを増やしただけです。

★4は以前1商品で2体ぶんまとめて配っていました。分けると「両方買う / 1体に絞る」の
選択が生まれます。

---

## 6. 星刻に必要なソウル（`SOULS_TO_NEXT`）

**元のレアリティ**と**いまの★**で決まります。数字はガチャの重複でもらえるソウル
（★3:30 / ★4:50 / ★5:150）の倍数に揃えてあるので「★5の1段目は重複4体ぶん」と数えられます。

| 星刻 | ★1の子 | ★2の子 | ★3の子 | ★4の子 | ★5の子 |
|---|---|---|---|---|---|
| ★1→2 | **10** | – | – | – | – |
| ★2→3 | 100 | **50** | – | – | – |
| ★3→4 | 150 | 200 | **90** | – | – |
| ★4→5 | 200 | 250 | 390 | **200** | – |
| ★5→6 | 200 | 300 | 450 | 600 | **300** |
| ★6→7 | 200 | 300 | 510 | 700 | 900 |
| ★7→8 | 200 | 300 | 540 | 800 | 1050 |
| ★8→9 | 200 | 350 | 570 | 800 | 1200 |
| ★9→10 | 240 | 350 | 600 | 800 | 1350 |
| **合計** | **1,500** | **2,100** | **3,150** | **3,900** | **4,800** |

**最初の1段は今までと同じ**にしてあります（★5→6 は 300、★4→5 は 200）。重くなるのは後半だけです。
★3→4 だけは 100 → 90（重複3体ぶん）に下がります。

以前は「いまの★」だけで決めていたので ★5の子がいちばん安く（2,800）、
**レアリティが高いほど完凸しやすい**という逆転が起きていました。この表は
**元レアリティで変わる唯一の設定**なので、公開ずみのイベントにも効きます。

## 7. 作ったあとに必ず測ること

`tools/` のハーネスで、次の2つの編成で各30回以上。

| 編成 | 何を見るか |
|---|---|
| Lv70 ★4 ワザLv3・遺物ルーンなし（総BP約11,000） | **EX1** が通れるか（60〜90%が目安） |
| Lv250 ★5 ワザLv10・遺物★5Lv80＋ルーンⅧ金×2（総BP約74,000） | **EX3** の勝率（30〜70%が目安）と1戦のラウンド数（12以下なら★3が取れる） |

勝率は試行ごとに±5ptぶれます。EX3は編成差が出る設計なので、対策編成と汎用編成の
両方で測ってください。

## ステージ効果（`stage.rules`）で書けること

```js
stage.rules = [{ who, side, stat, dmgDealt, dmgTaken, atk, when, whenTarget, shield, immune, label }]
```

| | 中身 |
|---|---|
| `who` | 当てはまるユニット。`{ species, element, role, family, ref }` のどれか（省略で全員） |
| `side` | `'ally'` / `'enemy'` / `'both'`（省略で both） |
| `stat` | `{ hp, str, pdef, mdef, spd }` を割合で。**戦闘に入るときに1回だけ**掛かる |
| `dmgDealt` | 与ダメージの増減（割合） |
| `dmgTaken` | 受けるダメージの増減（割合） |
| `atk` | `dmgDealt` / `dmgTaken` を `'phys'` か `'mag'` だけに絞る |
| `when` | **自分**の状態。`lowHp30` / `lowHp50` / `fullHp` / `burned` / `poisoned` / `shielded` |
| `whenTarget` | `dmgDealt` だけ。**殴る相手**の状態（「やけどの敵に+50%」はこれ） |
| `shield` | 受け取るシールドの量の増減（`+1` で2倍） |
| `immune` | かからなくなる状態異常の配列（`['stun']` / `['burn','poison']`） |
| `label` | 画面に出す文。**これが無いと表示されません** |

### 「物理耐性」は `dmgTaken` + `atk` で書く

防御値（`pdef` / `mdef`）は**引き算**なので、倍にしてもほとんど効きません。実測：

| | 4ラウンド |
|---|---|
| 効果なし | 4.2R |
| 敵の物防 ×3（`stat:{pdef:2}`） | **4.1R**（変わらない） |
| 敵の受ける物理ダメージ −2/3（`dmgTaken:-0.667, atk:'phys'`） | **5.2R** |

「耐性+200%」のつもりで `stat:{pdef:2}` と書くと**何も起きません**。
`{ dmgTaken: -0.667, atk: 'phys' }` と書いてください（ダメージが1/3になる）。

### 「〜のとき攻撃力+N%」は `stat.str` では書けない

`stat` は戦闘に入るときに1回だけ掛かるので、条件付きにできません。
「シールドを持っているあいだ攻撃力+50%」は `{ dmgDealt: 0.5, when: 'shielded' }` と書きます
（与ダメージが増えるので効きかたは同じ）。

テストは `tools/stage_rule_test.js`。

## イベントショップの値段の決めかた（素材）

**素材とワザ素材BOXの値段は手で決めないでください。** TierI 換算から計算します
（`eventMatPrice` / `eventBoxPrice` / `matT1Value`）。

```
TierI 換算 = 個数 × CRAFT_RATIO^(Tier-1)    … 合成が5個→1個 なので I=1 / II=5 / III=25 / IV=125

生の素材のメダル価格 = TierI換算 ÷ EVENT_MAT_PER_MEDAL   (= 1.5)  … 5メダル単位に丸める
ワザ素材BOXのメダル価格 = TierI換算 × EVENT_BOX_PREMIUM ÷ EVENT_MAT_PER_MEDAL
                        = TierI換算 そのまま              … BOXは種類を選べるぶん1.5倍の割高
```

| 品 | 中身 | TierI換算 | メダル |
|---|---|---|---|
| mat1 | TierI 各12個・証20個 | 44 | 30 |
| mat2 | TierII 各5個・証8個 | 90 | 60 |
| mat3 | TierIII 各3個・証5個 | 275 | 185 |
| mat4 | TierIV 各1個・証2個 | 500 | 335 |
| box1 | ワザ素材BOX TierI | 10 | 10 |
| box2 | 〃 TierII | 25 | 25 |
| box3 | 〃 TierIII | 75 | 75 |
| box4 | 〃 TierIV | 125 | 125 |

### なぜこの倍率か

- 1メダル = **0.2スタミナ**（ステージ10・イベントボーナス最大で1周100メダル／20スタミナ）
- メイン1スタミナ = **TierI換算 6.7**（神話級ハードのボス）
- → メダル1個ぶんの周回をメインに使うと TierI換算 1.33。**1.5 はそれより 1.12倍だけ得**

つまり「イベント中はイベントを回ったほうが少し得だが、メインを捨てるほどではない」に揃えてあります。
この釣り合いが崩れるので、**素材のドロップ量か合成倍率を変えたら `EVENT_MAT_PER_MEDAL` も見直してください**。

### 守ること

- **公開ずみのイベントの値段は変えない。** 新しい値段は `ev.econV2: true` を付けたイベントだけに効きます
- 値段を手で書かない。個数（`nEach` / `nRole`）を変えれば値段は勝手に追従します
- ソウル・召喚券・遺物・ゴールド・EXPポットは別枠（TierI換算では測れないので、いまは手で決めた値のまま）

テストは `tools/mat_economy_test.js` の7d節。
