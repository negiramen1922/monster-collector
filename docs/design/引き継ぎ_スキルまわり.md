## 1. スキル2の洗い出し（純バフ系スキル2）

### なぜやるのか

α0.3.000 の新バトルシステムで、**スキル1 → スキル2 の順に必ず回る**ようになりました
（`takeTurn` のスロット選び。前に使った次のスロットから順に、CTが明けているものを使う）。

以前は「スキル1が明いていればスキル1」だったので、スキル2は**たまにしか撃たれませんでした**。
実測で 1体1戦あたり 技2 0.48回 → **1.46回**。

その結果、**スキル2が純粋なバフだけのキャラは、2ターンに1回「殴らないターン」ができます**。
フェンリルの「暴風の遠吠え」（STR+30%・SPD+10）がその代表で、手数がそのぶん落ちます。

### やること

1. 全モンスターの `kitOf(m).skill2` を見て、**`pow` を持たない（＝ダメージを出さない）もの**を洗い出す
2. そのうち「バフだけ」「デバフだけ」「シールドだけ」「回復だけ」を分類する
3. 1体1戦あたりの DPS が新旧でどう変わったかを、その分類ごとに測る
4. 直しかたの案を出す（**先に数字と案。実装はユーザーの了解のあと**）

### 手がかり

- キット定義は `MONSTERS[].kit`（`index.html` 内）。`kitOf(m)` で取れます
- スキル2の使用回数は `takeTurn` のスロット選びで決まります。`u.lastSlot` が直前のスロット
- 案の方向として最低この3つは比べてください
  - **A**: 純バフのスキル2に `pow` を足す（撃ちながら殴る）
  - **B**: 純バフはスキル2ではなく**パッシブ**か**奥義に同梱**にする
  - **C**: スキル選びを「CTが明いている中でいちばん強いもの」に戻す（順番固定をやめる）
    → ただしユーザーは「なんで1じゃなくて2？が分からないので順番固定がいい」と言っています。**Cは分が悪い**

### 測りかた

`tools/harness.js` を使い、遺物・ルーンを装備した編成で N=30〜50 戦。
スクラッチパッドに使える下敷きがあります（過去のバランス調査スクリプト群）。
リポジトリには置かないでください（測定スクリプトはスクラッチパッド）。

## 2. スキル説明文の数値マークアップ（案1・合意ずみ）

### いまの問題

スキル詳細に **「説明文」と「現在の威力」が二重に出ています**。
説明文の数字は固定文字列なので、スキルLvを上げても変わりません。
そのため「現在の威力」という別の行を下に出して補っています。

### 決まった直しかた（案1）

説明文の中に **`{}`** で数字を書き、`{}` の中身を**スキルLvで計算して埋める**。
`{}` の部分は**黄色**にして「ここが変わる」と分かるようにする。
そして **「現在の威力」の行は消す**。

```
desc: '敵1体に威力{250}%の斬撃。'
      ↓ スキルLv8 なら
      '敵1体に威力 312% の斬撃。'   ← 312% が黄色
```

### 気をつけること

- `pow` と `effects[].v` は**自動で `{}` を付けられます**（`lvScale(lv)` を掛けるだけ）
- ただし **手書きの `run` の中の数字は自動化できません**。
  例：タイタンの奥義の「40%」は `run` 関数の中に直接書かれていて、
  説明文の数字と実際の計算が**別々に書かれている**状態です。ここは手で `{}` を付ける必要があります
- スケールのしかたは `lvScale(lv)` / `sv()` / `pv()` の3種類あります。
  **どれで伸びるかはキットごとに違う**ので、`skillUpgradePreviewLines()` の実装がそのまま答えです
  （あの関数は「戦闘エンジンと同じ計算」で今と次のLvを出しています）
- 持続ターンは `grownTurns` で Lv5・Lv10 の節目だけ伸びます。連続では変わりません

### 関係する場所

| | 場所 |
|---|---|
| 説明文 | `MONSTERS[].kit.*.desc` |
| 今の「現在の威力」 | `skillUpgradePreviewLines(m, field, lv)` |
| スケール | `lvScale(lv)` / `sv()` / `pv()` |
| 持続ターン | `grownTurns(u, kind, base, cat)` |

### 終わりの形

- スキル詳細から「現在の威力」の行が消えている
- 説明文の数字がスキルLvで動く
- `{}` だったところが黄色い
- `pow` を持つ全キットで、説明文の数字と `skillUpgradePreviewLines` の数字が**一致する**テストがある
  （ここが今いちばん壊れやすいところなので、テストは必須）

## 3. この2件をいっしょにやる理由

スキル2の洗い出しで「純バフのスキル2に `pow` を足す」案を採ると、
**その全キットの `desc` を書き直すことになります**。マークアップと同時にやるほうが二度手間になりません。

逆に、マークアップを先に入れてしまうと、そのあとキットを直すたびに `{}` の付け直しが要ります。
**洗い出し → 直しかたの決定 → マークアップ** の順がおすすめです。
