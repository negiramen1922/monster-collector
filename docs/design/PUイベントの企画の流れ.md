# PUイベントの企画の流れ

最終更新: 2026-10-05（モモタロウイベの企画のやり取りから）

ピックアップ（PU）イベントを企画するときの手順と、守ること。モモタロウイベ（`docs/提案資料/次回イベント案_モモタロウ.md`）を作ったときに、ユーザーから指摘を受けた点をまとめた。**新しいイベントを企画するときは、最初にこれを読むこと。**

---

## 0. 進め方の約束（いちばん大事）

| 約束 | 理由（実際にあった指摘） |
| --- | --- |
| **直したら、毎回全体を出す。** 直した所だけを出さない | 差分だけだと全体が見えず読みにくい |
| **★の数・属性・数値を、断りなく決めない。** 仮で置くときは「仮」と書いて確認する | お供を勝手に★3で作り、やり直しになった |
| **推測を事実として書かない。** 原因はコードやデータで確かめてから書く | 採点式のずれを「挑発のせい」と推測で書き、実際は防御バフの読み違いだった |
| **古い資料の値を使わない。** 報酬・経済の数字は今のコードで確かめる | EXの報酬に経済見直し前の値（結晶300/500/1000＋ソウル）を出してしまった |
| **ユーザーが変えた方針を、mainの古い資料より優先する。** 迷ったら `git log --all` で新しい資料を探す | 星刻特性の「段ごとの役割」は廃止済みなのに、mainの古い資料どおりに作った |
| **相性は良くしても、依存はさせない** | お供の性能を「モモタロウがいるとき」「きびだんご中」に寄せすぎた |

---

## 1. 前提をそろえる

- ★5の主役を決める（属性・ロール・種族）。立ち絵がリポジトリにあるか確認する
- 既存キャラの分布を見る。**★4の属性×ロールの空き枠は参考に出すが、無理に合わせない**（ユーザー方針）
- 読む資料
  - 星刻特性の手本: `docs/design/星刻特性_★5の8体.json`
  - ステージの作り方: `docs/design/イベントステージの作り方.md`
  - 経済: `docs/提案資料/経済見直し_実装指示書.md`（1イベントの石は約4,050石相当）
  - 前回のイベント案: `docs/提案資料/次回イベント案_*.md`

## 2. キャラを作る

### 顔ぶれ
- 主役★5が1体と、同時ピックアップの★4（何体か・★をいくつにするかはユーザーが決める）
- イベント用の★3（敵として出す子）を足すこともある（例: アカオニ・アオオニ）

### 性能の作り方
- **1体だけで編成しても戦えるようにする。** 相性は「STRアップ中」「バフを受けている間」「味方のデーモンの数」など、誰でも満たせる条件で作る。主役やその技を名指しで前提にしない
- 威力は採点式（`tools/balance/power_lib.js`）の予算で見る。スキルは予算の85〜115%、奥義は100〜130%
  - 予算: CT3 22 / CT4 27 / SP100 55 / SP110 62 / SP120 70。★3 ×1.0 / ★4 ×1.1 / ★5 ×1.2
  - **注意**: 採点式は防御バフ・デバフ（ポイント加算）を割合として読んでしまう不具合がある（39スキルが10〜40倍）。直るまでは手で計算する
- **採点だけで決めない。同じレア・同じロールの既存キャラと並べて比べる**（単体奥義を採点に合わせて550%にしかけたが、既存の★4は340〜400%＋強い追加効果だった）
- 条件つきのダメージアップは、次のルールで決める

#### 条件つきダメージアップのルール

**上がる量 = 条件の段階 × どの攻撃に乗るか × だれに乗るか**（5%単位に丸める）

| 条件の段階 | 例 | 値 |
| --- | --- | --- |
| ほぼいつも満たす | 自分のシールド中、いつも狙う後衛 | 10% |
| 自分で作れる | 自分で付けたやけど・デバフ、編成で決まる条件 | 15% |
| 敵や状況しだい | デーモン、HPが50%以下 | 20% |
| 満たしにくい | 拘束・気絶、きつい編成条件 | 30% |

| どの攻撃に乗るか | 倍率 |
| --- | --- |
| すべての攻撃 | ×1 |
| 通常攻撃だけ | ×1.25 |
| スキル1つだけ／奥義だけ／パッシブの追加攻撃だけ | ×1.5 |

| だれに・いつ | 倍率 |
| --- | --- |
| 自分だけ | ×1 |
| 味方全体 | ×0.5 |
| スキルや奥義で付く、数ターンだけのもの | ×1.5 |

- タンク・サポーターは1つ上の段階の値を使う（上限30%）
- ★10は表の外でよい

### 説明文の書き方（2026-10-05 ユーザー指示）

- 攻撃: 「〈対象〉に威力N%の〈物理/魔法〉攻撃を〈M回〉行う。命中時に〈状態〉（〈量〉）を〈Tターン〉付与する」
  - 例: 「敵後衛単体に威力40→62%の魔法攻撃を4回行う。命中時に鈍化（-15→23%）を2→3ターン付与する」
- 強化・回復も同じ形: 「〈対象〉に攻撃力上昇（+20→31%）を2→4ターン付与する」「〈対象〉を回復する（回復量250→388%）」
- **スキルLvで変わる数値は「Lv1→Lv10」で書く**（遺物の「初期→最大」と同じ）。スキル・奥義は上限10でLv10が1.5倍、パッシブは上限5でLv5が1.5倍（`docs/提案資料/パッシブLvの区切り見直し.md`）
- **Lv1の値は10の倍数（小さい値は偶数）にする**。最大の1.5倍も必ず整数になる（15%ではなく16%）
- **星刻特性で条件を広げるときは、何が乗るのかまで書く**。例: 「鈍化状態の敵にも、与ダメージ+10→15%が乗るようになる」。数値を変えるときは「-20→30% が -30→45% になる」のように前後を両方書く
- 星刻特性でパッシブの数値そのものを上げない（パッシブLvと同じものを伸ばすことになる）。条件を広げる・別の効果を足す
- **パッシブには、Lvで伸びる数値を必ず1つ持たせる**（復活だけ・耐性だけ、のような伸びないパッシブは作らない）ターン数は、味方への付与がLv5とLv10で+1ずつ、敵への付与がLv10で+1（上限5）。通常攻撃・挑発・回数・CT・SP・確率は変わらない（`lvScale` / `grownTurns`）
- 状態の名前は `docs/名称置き換え資料.md` の「状態の名前」にそろえる（攻撃力上昇・攻撃力低下・加速・鈍化 など）
- パッシブの伸び方は `docs/提案資料/パッシブLvの区切り見直し.md` で見直し中（Lv1〜5にして、1回の素材を増やす案）

### 星刻特性（★6〜★10）

**2026-10-06 決定: 段ごとに「どの枠を強くするか」を決める**（以前の「★6得意な場面…★10決め技」とは別のルール。★6が素のステータスアップだけになってつまらない、という理由）

| ★ | 強くする枠 | 中身の例 |
| --- | --- | --- |
| ★6 | スキル1 | 対象を広げる・回数を増やす・CTを縮める・ターン数を延ばす・追加効果を足す。いちばん多く使う技なので、いちばん多くの人が届く★6で変化が見える |
| ★7 | パッシブ | 条件を広げる・別の効果を足す |
| ★8 | スキル2 | 同上 |
| ★9 | 奥義 | 同上 |
| ★10 | そのキャラのコンセプト | 大きめの強化。**キャラごとに「コンセプト（想定している立ち回り）」を書き、★10はそこから理由を説明できるものにする** |

- 素のステータスアップ（最大HP+15%など）だけの段は作らない
- **Lvで伸びる数値（威力・効果量）は星刻で上げない**。スキルLv・パッシブLvと同じものを伸ばすことになるため。対象・回数・CT・持続・条件・追加効果で強くする
- 条件を広げるときは、**数値を書かずにパッシブの効果を名指しする**（例: 「自分より遅い敵への与ダメージアップが、鈍化状態の敵にも乗るようになる」）。数値を書くと、上乗せされると読まれやすい。数値を変えるときは前後を両方書く（例: 「-20→30% が -30→45% になる」）
- **自分のパッシブで復活するキャラは、復活しても「倒れた」に数えない**（★2・★3の「味方が1体も倒れない」に触れない）。ほかの味方による蘇生は数える。味方を守る効果は「倒れる代わりに踏みとどまらせる」形にすると、この判定に触れない
- 新しく作るキャラは、はじめから「伸びる数値」をパッシブに1つ持たせる

### 防御とシールドの数値の目安（2026-10-06）

- **物理防御・魔法防御の上昇・低下は、%ではなくポイントで書く**（防御1ポイント＝受けるダメージ1%カット。0未満にはならないので、下げすぎても無駄になる）
  - 敵への低下: -6〜-10（既存キャラはこの範囲）。素の防御が5〜10の敵が多いので、-20は多くの敵で余る
  - 自分・味方への上昇: +10〜+20（既存キャラは+10〜+25）
- **シールドは最大HPの割合**で書く（上限は最大HPの100%）

| 対象 | スキル | 奥義 | 既存キャラの例 |
| --- | --- | --- | --- |
| 自分だけ | 20〜35% | 30〜50% | 氷の装甲 20%・鍛冶の盾 25%・アクアバリア 30%・ティターンの城壁 40% |
| 味方全体 | 5〜10% | 15〜20% | サンシールド 10%（術者の最大HP）・氷壁 15%（術者の最大HP） |

- 味方全体のシールドは「術者の最大HP」か「それぞれの最大HP」かを必ず書く。タンクの最大HPが基準だと量が大きくなる

## 3. 遺物

| | 形 | 数値（初期→最大） |
| --- | --- | --- |
| 専用遺物（★5） | 無条件 / 条件つき（属性・種族・ロール） / 主役だけ | 15→30% / 15→30% / 16.5→33% |
| 配布遺物（★4） | 無条件 / 主役の属性 / 主役の属性 | 12.5→25% ×3 |

- 基本ステータスはプリセット（`docs/design/遺物ステータスのプリセット.json`）から、主役のステータスの寄せ方に合わせて選ぶ
- 専用遺物は、遺物ガチャが今のバナーの主役の分を**自動でピックアップ**する（追加の作業なし）
- 配布遺物はガチャに出さない。**イベントショップで本体（200メダル×1）と重複（200メダル×4）を売る**（2026-10-05 から。層の初回クリアで配る形はやめた）。同じ属性の既存の配布遺物とは別の型にして、2択にする
- 遺物の完凸は「凸4回」（本体＋重複4個）。モンスターの★10とは別の仕組み。遺物スキルLvは別で上限10

## 4. クエストステージ（10層）

- `EVENTS` に1件足す。前回の形（`waveSizes: [3,3,4,4,5]`、`escortPools` で層ごとに護衛を変える、`tiers` 10段）をそのまま使う
- ボスは主役（ソウルと「仲間になる」は主役のボスから出る仕組みのため）。話の筋は、ボスが主役であることに合わせて考える
- 護衛は属性を1つに寄せない。同じ科から広く取る
- 最終ウェーブを固定したいとき（主役＋お供など）は、今のコードにはその仕組みがない（`buildEventStages` は「ボス＋護衛を順番」）。実装で足す

## 5. EXステージ（EX1〜EX3＋HELL）

| 段 | 推奨Lv | ボスの★ | 雑魚の★ | 敵ワザLv | 初回クリアの石 |
| --- | --- | --- | --- | --- | --- |
| EX1 | 70〜85 | 6 | 4 | 8 | 100 |
| EX2 | 200 | 8 | 5 | 10 | 200 |
| EX3 | 300 | 10 | 6 | 12 | 400 |
| HELL | 300 | 10 | 10 | 12 | 500。★3クリアで称号と、主役の入った派手なアイコンフレーム |

- HELLは、雑魚にも星刻特性があるイベントで足す「クリアできるものならしてみろ」の段（モモタロウイベから）
- 各段10体まで。内訳: 主役1 / 抱き合わせ★4 / その他の★4 / ★3以下
- **主役以外の★5は入れない**（難易度とソウルの出どころのため）
- ステージ効果は「編成が変わるルールを1本は入れる」。段が上がるごとにルールを足す形にする（例: HELLだけ主役のHP+100%）
- 雑魚に低レアの汎用キャラ（ゴブリンなど）を出さない。世界観に合う子がいなければ、★3を新しく作ってよい（例: エインヘリャル）
- ソウルは初回クリアでは出さない。クリアのたびのドロップ（`EX_MOB_SOUL_RATE`）で出る

## 6. 作ったあとに測る

- 新キャラ: 相棒と組んだときの伸びと、1体だけのときの強さ
- クエスト10層: 3パーティ（高レア / 基本B / 気絶）で各層40戦
- EX1: Lv70・★4・ワザLv3・遺物ルーンなし（総BP約11,000）で60〜90%
- EX3: Lv250・★5・ワザLv10・遺物★5Lv80＋ルーンⅧ金×2（総BP約74,000）で30〜70%、1戦12ラウンド以下
- HELL: Lv300・★10・ワザLv12・遺物とルーンを積んだ編成で10〜40%

## 7. 出すもの

1. 企画の資料: `docs/提案資料/次回イベント案_<主役>.md`（キャラ・遺物・ステージ・決めてほしいこと）
2. 実装指示書: `docs/提案資料/<主役>イベ_実装指示書.md`（別のセッションで実装するとき）
3. 試験場で遊んで確かめる場合は、`index.html?lab=<名前>` の形（バベル試験場・チュートリアル試験場と同じ。本番のセーブには書かない）
