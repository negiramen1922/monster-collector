# 防御を「そのまま%カット」にする（α0.3.005）

引き算の防御は**数字を見ても強さが分からない**（物防464と言われても何%減るのか分からない）。
そのうえステージ効果で「敵の物防×3」と書いても**実測で 4.2R → 4.1R** とほぼ何も起きなかった。
そこで **防御値 = そのままダメージカット%** にした。物防24なら受ける物理ダメージが24%減る。

---

## 1. どう変わったか

```
旧: preCut = max(raw × 0.10, raw − def)     def はレベル・★で伸びる(タイタンLv300で464)
新: preCut = raw × (1 − def/100)            def は素の値のまま(タイタンは31%)
```

### 出発点

引き算のころ、防御が**実際に削っていた割合**を測ったら、素の防御値とほぼ同じだった
（タンク 素21.4 / 実測22.3%、シューター 5.5 / 5.9%）。STR と防御が同じ率で伸びるので、
引き算の割合が**レベルに関係なく一定**だったため（タンクは Lv1 でも Lv300 でも 22.3%）。
つまり「素の値をそのまま%として読む」だけで、ほぼ同じバランスになる。

そこから、**素の防御をタンク20が上限になるように ×0.645 で縮めた**。
数字が小さいほうが「何%カットか」を直感で掴みやすく、上乗せを足し算にしたときの
伸びしろも残る。

### 上乗せは全部ポイント加算（掛け算はゼロ）

割合で乗せると2つ困ることがある。

1. **素の防御が高いタンクだけが得をする。** 九尾（素4）に「物理防御+40%」を掛けても +1.6。
   サポーターの防御バフが柔らかい子を守れない
2. **積む順番で結果が変わる。** ルーンを足したあとに%を掛けると、ルーンぶんにも掛かる。
   実測でタンクが 素31 → ルーン60 → 遺物75 → 陣形83 → シナジー112 と複利で膨らんだ

なので `stat.pdef` / `bonus.pdef` / `pdefUp` / `defBonus` / 陣形 / 種族シナジー / 遺物パーク、
**全部ポイント加算**にした。画面の数字は常に「何%カットか」で、どの上乗せも「+N%」。

### 変えたところ

| | 中身 |
|---|---|
| 素の防御 | **×0.645** に縮小（タンク 9〜20 / アタッカー 3〜10 / シューター 1〜8 / サポート 3〜9 / トリックスター 4〜9） |
| `scaledStats` | pdef / mdef に**レベル・★の倍率を掛けない** |
| `applyStatBonus` | `def` / `pdef` / `mdef` は**ポイント加算**（`addDefPoints`）。hp / atk / spd は今までどおり割合 |
| `applyStageRules` | `stat.pdef` / `stat.mdef` はポイント加算（`pdef: 8` で +8%カット） |
| `buildUnit` | 敵の pdef / mdef に**`enemyMult`（ステージLv補正）もボス補正も掛けない**。掛けると高Lvのステージで全員が上限99%（＝ほぼ無敵）になる |
| `effDef` | `base + バフ − デバフ + パッシブ`（全部ポイント）。上限 `DEF_POINT_CAP = 99` |
| `strike` / `magicFixed` / 肩代わり | `raw × (1 − defCutOf(def))` |
| `DAMAGE_MIN_RATIO`（10%の床） | 廃止。上限99%が代わり |
| ルーンの pdef / mdef | **%ではなくポイント加算**（1ポイント = 1%カット） |
| `battlePower` | 防御の重み 4 → **`BP_DEF_WEIGHT = 70`**（BPの表示が動かないように） |
| ステータス画面 | 「物防 464」→「**物防 31%**（ダメージを31%カット）」。レベルの伸び幅は出さない |

## 2. 上限

| | |
|---|---|
| `DEF_POINT_CAP` | **99**。ふだんは50を超えない想定。99まで積めるのは、ステージ効果で「確定ダメージを使わせる」ようなときだけ |
| `RATIO_CAP`（防御貫通） | **0.8**。貫通をどれだけ積んでも、相手の防御ポイントは**80%までしか削れない** |
| `CUT_CAP`（被ダメージ軽減） | **0.8**。防御とは別の層で、あとから掛かる |

防御と軽減は**別々に掛かる**（`raw × (1−def%) × (1−cut%)`）。
防御50% × 軽減80% = 実質90%カット。防御99%（ステージ効果）だと軽減こみで99.8%。

### 防御貫通の効きかた

```
実際の防御ポイント = 相手の防御 × (1 − min(0.8, 貫通))
```

タイタン（物防31%）に対して：

| 貫通 | 残る防御 |
|---|---|
| なし | 31% |
| 30% | 21.7% |
| 50% | 15.5% |
| 80%（上限） | 6.2% |
| 100%と書いても | 6.2%（80%止まり） |
| `ignoreDef` のワザ | **0%**（完全に無視） |

**防御99%の壁は貫通では壊せない**（80%削っても19.8%残る）。
壊すには `ignoreDef` の確定ダメージが要る。これがステージ効果で99を使うときの狙い。

### やけど・毒

状態異常のダメージは `strike` を通らず直接HPを削るので、**防御を完全に無視する**（貫通100%扱い）。
これは仕様。防御が読めるようになったぶん「毒は防御を無視する」が分かりやすくなった。

## 3. ルーン

防御は素の値が 2〜33 しかないので、**%増しだと弱すぎる**（Ⅹの22%でも +4.4ポイントにしかならない）。
ポイント加算に変えた。**ルーンは `{tier, main, subs:[{stat,q}]}` しか保存していない**ので、
表を書き換えるだけで**既存のルーンも自動で新しい値になる**（移行処理は要らない）。

| | Ⅰ | Ⅴ | Ⅷ | Ⅹ |
|---|---|---|---|---|
| メイン | 1.5 | 3.1 | 4.3 | **5** |
| サブ（1個） | 1 | 1 | 1〜2 | 1〜2 |

## 3b. 上乗せの予算

「フル投資のタンクが50%を超えないこと」を目安に決めた。

| | ポイント |
|---|---|
| ルーン（防御メイン×2＋防御サブ×3・Ⅹ） | **+16** |
| 遺物パーク（`pct` 2 / 2 / 3 / 3 / 4）×2個 | **+6** |
| 双璧の陣（前衛） | **+1** |
| ドワーフのシナジー（2体 / 3体 / 5体） | +1 / +2 / **+4** |
| バフ（`pdefUp` 3 / 4 / 5 / 6 / 8） | +3〜**+8**（一時的） |

積み上げの実測：

| | 素 | ＋ルーン | ＋遺物 | ＋陣形 | ＋ドワーフ5 | ＋バフ |
|---|---|---|---|---|---|---|
| タイタン（タンク） | 20% | 36% | 42% | 43% | **47%** | 55% |
| アバドン（アタッカー） | 9% | 25% | 31% | 32% | 36% | 44% |
| 九尾（シューター） | 4% | 20% | 26% | 27% | 31% | 39% |

装備で乗る量は誰でも同じなので、**タンクとの差は素の防御の差（16ポイント）がそのまま残る**。

### 覚悟しておくこと

防御は**積むほど1ポイントの価値が上がる**（40%→50%のほうが 0%→10% より効く）。
そのため防御ルーン1個は「HPルーン1個の1/3くらい」にしか見えないが、
4枠ぜんぶ防御にすると急に強くなる。**「全部積むか、積まないか」のステータス**になっている。

## 4. 測った結果

### 本気編成（★10 Lv220・BP 約10万）

BP は **101,789 → 102,981** でほぼ据え置き（`BP_DEF_WEIGHT = 70`）。
どのステージも勝率100%・★3率100%で、旧システムから動かなかった。

### 中盤の編成（★5 Lv165・5体）

| ステージ | 旧（引き算） | 新（%カット・最終） |
|---|---|---|
| q5_04 | 100% / 100% | 100% / 100% |
| q5_08 | 100% / 100% | 100% / 98% |
| q5_10 | 100% / 72% | 100% / 82% |
| q6_05 | 100% / 0% | 100% / 0% |
| q6_10 | 98% / 42% | **81%** / 22%（150戦） |
| q7_05 | **70%** / 43% | **58%** / 17%（150戦） |

素の防御を ×0.645 に縮めたので、**両陣営とも削る割合が下がり、全体にダメージが通りやすくなった**。
終盤の編成（全勝）には影響しないが、**格上に挑むときだけ 10〜15ポイントぶん厳しくなっている**
（q7_05 は Lv165 の編成で推奨Lv260 に挑んだ場合）。

縮める前（素の防御そのまま）だと q7_05 は 100% まで楽になっていたので、
ここは「タンクの上限を20にする」ことと引き換えの調整。厳しすぎるなら、
縮小率を 0.645 → 0.75 に戻す（タンク上限23）か、装備の予算を増やす。

### 副作用：格上に挑んだときの壁の作りかたが変わった

旧システムでは敵の防御が**ステージのレベルで伸びていた**ので、レベル差がそのまま
「ダメージが通らない」壁になっていた。新システムでは防御は**編成の性質だけ**なので、
格上との差は **HPとSTR**が作る。勝率で見ると結果は同じところに落ち着いたが、
**難度を作るレバーの中身が変わっている**。次に難度を動かすときはHP・STRか、
ステージ効果（いまは素直に効く）で作ること。

## 5. まだやっていないこと

- **遺物の防御**。`RELIC_STAT_LABEL` に `pdef` / `mdef` / `def` / `pierce` / `cut` の定義はあるが、
  いま防御を配っている遺物は**58個中0個**。次に作るときの数字は新しい基準で決める
- **素の防御の「寄り」**。いまは全員が物防・魔防を両方そこそこ持っている。
  「物理寄りのアタッカーは 物防5 / 魔防0」のように**片方を0にする**と性格が出るが、
  139体ぶんの設計になるので、キャラを足す・見直すときに少しずつやる
  （0はポイント加算と相性がいい。掛け算だと 0×1.4=0 で永久に0のまま）
- **九尾EXのステージ効果**。「物理耐性+200%」は `dmgTaken` の読み替えが要らなくなり、
  `stat:{pdef:...}` で素直に書けるようになった。数字を決め直す
- **総力戦・PVP・深淵回廊**の再調整。特にPVPは、会心が防御で等しく削られるようになったので
  **防御型の相手が今までより硬い**

テストは `tools/defense_ratio_test.js`。
