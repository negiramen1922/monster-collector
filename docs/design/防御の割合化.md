# 防御を「そのまま%カット」にする（α0.3.005）

引き算の防御は**数字を見ても強さが分からない**（物防464と言われても何%減るのか分からない）。
そのうえステージ効果で「敵の物防×3」と書いても**実測で 4.2R → 4.1R** とほぼ何も起きなかった。
そこで **防御値 = そのままダメージカット%** にした。物防24なら受ける物理ダメージが24%減る。

---

## 1. どう変わったか

```
旧: preCut = max(raw × 0.10, raw − def)     def はレベル・★で伸びる(タイタンLv300で464)
新: preCut = raw × (1 − def/100)            def は素の値のまま(タイタンは31%)
```

### なぜ数字を作り直さなくていいのか

引き算のころ、防御が**実際に削っていた割合**を測ったら、素の防御値とほぼ同じだった。

| ロール | 素のpdef（平均） | 旧システムで実際に削っていた% |
|---|---|---|
| アタッカー | 8.6 | 8.8% |
| シューター | 5.5 | 5.9% |
| サポート | 8.0 | 8.4% |
| タンク | 21.4 | 22.3% |
| トリックスター | 9.5 | 10.1% |

STR と防御が同じ率で伸びるので、引き算の割合が**レベルに関係なく一定**だった
（タンクは Lv1 でも Lv300 でも 22.3%）。
つまり「素の値をそのまま%として読む」だけで、今までとほぼ同じバランスになる。

### 変えたところ

| | 中身 |
|---|---|
| `scaledStats` | pdef / mdef に**レベル・★の倍率を掛けない** |
| `buildUnit` | 敵の pdef / mdef に**`enemyMult`（ステージLv補正）もボス補正も掛けない**。掛けると高Lvのステージで全員が上限99%（＝ほぼ無敵）になる |
| `effDef` | 上限 `DEF_POINT_CAP = 99` でクランプ。バフ・デバフ・パッシブは今までどおり掛け算 |
| `strike` / `magicFixed` / 肩代わり | `raw × (1 − defCutOf(def))` |
| `DAMAGE_MIN_RATIO`（10%の床） | 廃止。上限99%が代わり |
| ルーンの pdef / mdef | **%ではなくポイント加算**（1ポイント = 1%カット） |
| `battlePower` | 防御の重み 4 → **`BP_DEF_WEIGHT = 40`**（BPの表示が動かないように） |
| ステータス画面 | 「物防 464」→「**物防 31%**（ダメージを31%カット）」。レベルの伸び幅は出さない |

## 2. 上限

| | |
|---|---|
| `DEF_POINT_CAP` | **99**。ふだんは50を超えない想定。99まで積めるのは、ステージ効果で「確定ダメージを使わせる」ようなときだけ |
| `RATIO_CAP`（防御貫通） | **0.8**。貫通をどれだけ積んでも、相手の防御ポイントは**80%までしか削れない** |
| `CUT_CAP`（被ダメージ軽減） | **0.8**。防御とは別の層で、あとから掛かる |

防御と軽減は**別々に掛かる**（`raw × (1−def%) × (1−cut%)`）。
防御50% × 軽減80% = 実質90%カット。防御99%（ステージ効果）だと軽減こみで99.8%。

### 防御貫通の効きかた

```
実際の防御ポイント = 相手の防御 × (1 − min(0.8, 貫通))
```

タイタン（物防31%）に対して：

| 貫通 | 残る防御 |
|---|---|
| なし | 31% |
| 30% | 21.7% |
| 50% | 15.5% |
| 80%（上限） | 6.2% |
| 100%と書いても | 6.2%（80%止まり） |
| `ignoreDef` のワザ | **0%**（完全に無視） |

**防御99%の壁は貫通では壊せない**（80%削っても19.8%残る）。
壊すには `ignoreDef` の確定ダメージが要る。これがステージ効果で99を使うときの狙い。

### やけど・毒

状態異常のダメージは `strike` を通らず直接HPを削るので、**防御を完全に無視する**（貫通100%扱い）。
これは仕様。防御が読めるようになったぶん「毒は防御を無視する」が分かりやすくなった。

## 3. ルーン

防御は素の値が 2〜33 しかないので、**%増しだと弱すぎる**（Ⅹの22%でも +4.4ポイントにしかならない）。
ポイント加算に変えた。**ルーンは `{tier, main, subs:[{stat,q}]}` しか保存していない**ので、
表を書き換えるだけで**既存のルーンも自動で新しい値になる**（移行処理は要らない）。

| | Ⅰ | Ⅴ | Ⅷ | Ⅹ |
|---|---|---|---|---|
| メイン | 3 | 6.2 | 8.6 | **10** |
| サブ（1個） | 1 | 1〜2 | 1〜2 | 1〜3 |

- 防御型に寄せたタンク（物防メイン×2＋物防サブ×3・Ⅹ）：31 + 20 + 約6 = **約57%**
- 理屈のうえの最大（メイン4＋サブ16ぜんぶ物防・Ⅹ）：31 + 40 + 48 = 119 → **上限99でカット**

## 4. 測った結果

### 本気編成（★10 Lv220・BP 約10万）

BP は **101,789 → 102,027** でほぼ据え置き（`BP_DEF_WEIGHT = 40`）。
勝率・★3率・ラウンド数はどのステージも動かなかった（元から全勝）。

### 中盤の編成（★5 Lv165・5体）

| ステージ | 旧 勝率/★3率 | 新 勝率/★3率 |
|---|---|---|
| q5_04 | 100% / 100% | 100% / 100% |
| q5_08 | 100% / 100% | 100% / 87% |
| q5_10 | 100% / 72% | 100% / **52%** |
| q6_05 | 100% / 0% | 100% / 0% |
| q6_10 | 98% / 42% | 100% / **80%** |
| q7_05 | **70%** / 43% | **100%** / **92%** |

### いちばん大きい副作用：格上に挑むのが楽になった

旧システムでは、敵の防御が**ステージのレベルで伸びていた**ので、
レベル差があると「ダメージが通らない」壁になっていた（q7_05 で勝率70%）。

新システムでは防御は**編成の性質だけ**で決まるので、格上に挑んでも差は **HPとSTRだけ**になる。
→ **レベル差の壁がひとつ消えた**（q7_05 が 70% → 100%）。

読みやすさと引き換えに、難度を作るレバーが1本減っている。
足りなければ HP・STR か、ステージ効果（いまは素直に効く）で作ることになる。

## 5. まだやっていないこと

- **遺物の防御**。`RELIC_STAT_LABEL` に `pdef` / `mdef` / `def` / `pierce` / `cut` の定義はあるが、
  いま防御を配っている遺物は**58個中0個**。次に作るときの数字は新しい基準で決める
- **防御バフ・デバフの説明文**。`effDef` が掛け算なので強さは変わらないが、
  「物理防御+40%」が「+8ポイント」に見えるようになる。`pdefUp` 20箇所 / `mdefUp` 12箇所 /
  `pdefDown` 5箇所 / `defBonus` パッシブ6箇所。スキル説明文のマークアップと同時にやるのが得
- **九尾EXのステージ効果**。「物理耐性+200%」は `dmgTaken` の読み替えが要らなくなり、
  `stat:{pdef:...}` で素直に書けるようになった。数字を決め直す
- **総力戦・PVP・深淵回廊**の再調整。特にPVPは、会心が防御で等しく削られるようになったので
  **防御型の相手が今までより硬い**

テストは `tools/defense_ratio_test.js`。
